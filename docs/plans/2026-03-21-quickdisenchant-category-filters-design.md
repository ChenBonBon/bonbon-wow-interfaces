# QuickDisenchant 分类筛选设计

## 背景

QuickDisenchant 当前主窗口和候选窗口都以 3x3 宫格显示候选装备，并通过滚动展示更多物品。随着 Wowhead 黑名单过滤接入完成，主流程已经稳定，但当背包里可分解装备较多时，用户仍需要靠手动浏览快速定位目标。

用户希望在插件顶部增加一组互斥筛选条件，优先支持按“装备大类/护甲类型”过滤候选物品，同时保持现有主窗口、候选窗口和分解流程不变。

## 目标

为主窗口和候选窗口同时增加顶部分类筛选，并统一切换到更宽的宫格布局：

- 顶部提供互斥分类：`全部`、`武器`、`布甲`、`皮甲`、`锁甲`、`板甲`、`其他`
- 主窗口与候选窗口共用同一个当前筛选
- 两个窗口都改为 `4 列 x 2 行` 的可见布局
- 超出可见范围仍通过滚动查看
- 关闭窗口后，下次 `/qd` 默认回到 `全部`

## 方案选择

### 方案 1：顶部互斥标签按钮（采用）

在窗口标题下方增加一行紧凑分类按钮，点击后切换当前筛选，并基于筛选结果重新渲染宫格。

优点：
- 交互最直接
- 不需要级联菜单或置灰逻辑
- 与当前图标宫格浏览模式最匹配

### 方案 2：下拉菜单

通过一个筛选下拉框切换类型。

缺点：
- 额外多一步点击
- 不如顶部标签直观

### 方案 3：两级筛选（大类 + 子类）

先选武器/护甲，再选具体护甲类型。

缺点：
- 第一版过重
- 不符合当前“快速扫一眼马上点”的使用方式

## 布局设计

主窗口和候选窗口统一调整为：

- `COLUMNS = 4`
- `VISIBLE_ROWS = 2`

这样可以让顶部 7 个筛选项保持单行展示，同时不显著增加窗口高度。

示意布局：

```text
┌──────────────────────────────────────────┐
│               可分解装备 (18)            │
│                                          │
│ [全部] [武器] [布甲] [皮甲] [锁甲] [板甲] [其他] │
│                                          │
│ [图标] [图标] [图标] [图标]              │
│ [图标] [图标] [图标] [＋ ]               │
│                                          │
│                   [分解]                 │
└──────────────────────────────────────────┘
```

## 分类规则

分类在扫描结果之上做视图过滤，不改变底层候选扫描规则。

- `全部`
  - 显示当前全部候选物品
- `武器`
  - `itemClassID == Weapon`
- `布甲`
  - `itemClassID == Armor` 且护甲子类为布甲
- `皮甲`
  - `itemClassID == Armor` 且护甲子类为皮甲
- `锁甲`
  - `itemClassID == Armor` 且护甲子类为锁甲
- `板甲`
  - `itemClassID == Armor` 且护甲子类为板甲
- `其他`
  - 所有不属于上述分类、但仍符合可分解候选规则的物品
  - 包括但不限于：专业装备、戒指、项链、饰品、斗篷、盾牌、副手物品等

## 数据流与状态

新增一个共享运行时状态，例如 `QD.state.activeFilterKey`。

行为约定：
- `/qd` 扫描时重置为 `全部`
- 点击任一分类按钮后更新 `activeFilterKey`
- `refreshMainWindow()` 和 `refreshCandidateWindow()` 都基于同一分类过滤结果渲染
- 主窗口关闭时仍按现有逻辑同步关闭候选窗口

## UI 行为细节

- 标题中的数量显示当前筛选后的数量，而不是总候选数量
- 主窗口中的 `+` 按钮仍然遵循“出现在当前显示列表的第 n+1 格”规则
- 候选窗口也应用相同筛选条件，仅显示当前分类下尚未选中的物品
- 筛选按钮是互斥的，当前选中项用更亮的文字或边框区分

## 影响范围

预期只需要修改：
- `QuickDisenchant/Core.lua`
- `QuickDisenchant/Data.lua`
- `QuickDisenchant/UI.lua`
- 可能少量触及 `QuickDisenchant/Events.lua`（用于 `/qd` 时重置筛选）

不需要修改：
- 分解安全按钮逻辑
- 白名单逻辑
- Wowhead 黑名单过滤逻辑
- crawler 相关代码

## 验证

由于本机没有 Lua 解释器和现成 Lua 单测入口，本次主要采用：
- 最小范围代码改动
- 静态代码检查与 diff 核对
- 游戏内手工验证

推荐游戏内验证步骤：
1. `/reload`
2. `/qd`
3. 检查主窗口顶部是否出现 7 个筛选按钮
4. 逐个点击分类，确认主窗口数量与物品列表同步变化
5. 点击 `+` 打开候选窗口，确认候选窗口使用相同筛选条件
6. 检查 `4x2` 布局和滚动行为是否正常
