# QuickDisenchant 筛选按钮数量与开关样式设计

## 背景

QuickDisenchant 已经具备分类筛选能力，主窗口与候选窗口都可以按 `全部 / 武器 / 布甲 / 皮甲 / 锁甲 / 板甲 / 其他` 进行互斥过滤。当前筛选按钮已经可用，但仍有两个体验问题：

1. 用户看不到每个分类下当前背包候选物品的数量。
2. 按钮的视觉反馈还不够像“开关”，选中与未选中状态的层次感不够明显。

## 目标

在不改标题文案的前提下，增强顶部筛选按钮的信息量和交互辨识度：

- 每个筛选按钮后显示当前分类的候选数量，例如 `武器(4)`。
- 数量统计口径为：
  - 当前背包中该分类的全部候选数
  - 基于 `QD.state.allItems`
  - 不区分是否已加入主窗口、不区分白名单状态
- 筛选按钮改成明显的“开关样式”
  - 未选中时呈现立体弹起效果
  - 选中时呈现按下去的效果

## 方案选择

### 方案 1：按钮文字直接附带数量 + 切换贴图/偏移表现按压状态（采用）

例如：

- `全部(18)`
- `武器(4)`
- `布甲(3)`

按钮仍保持单行排列，不新增第二行说明文字。通过边框、背景色、文字颜色和文字位置偏移模拟“弹起/按下”状态。

优点：
- 信息最集中
- 不增加窗口高度
- 和现有 4x2 布局兼容最好

### 方案 2：按钮下方单独显示数量

优点：
- 视觉上更规整

缺点：
- 顶部区域高度会继续增加
- 破坏当前紧凑布局

## 数据来源

数量统计统一来自 `QD.state.allItems` 的分类统计，而不是来自主窗口已选列表。

原因：
- 用户更关心背包里该分类一共有多少候选物品
- 如果只统计已选中数量，按钮信息会失真
- 该统计更适合作为“筛选导航”的总览信息

统计规则：
- `全部`：`#QD.state.allItems`
- 其他分类：遍历 `QD.state.allItems`，用已有的 `QD.getItemCategoryFilterKey(item)` 分类计数

## UI 表现

### 未选中按钮

- 边框略亮
- 背景较浅，保留立体感
- 文字颜色稍暗
- 文字基准位置保持正常

### 选中按钮

- 边框与背景更深、更实
- 文字颜色更亮
- 文字位置轻微下移，模拟按下感
- 不再只是简单换色，而是强调“按压”状态

## 影响范围

主要修改：
- `QuickDisenchant/UI.lua`
- 可能补充少量统计辅助到 `QuickDisenchant/Data.lua`

不需要修改：
- 扫描逻辑
- 分解逻辑
- 白名单逻辑
- crawler 相关代码

## 验证

由于本机没有 Lua 运行环境，本次验证仍以静态检查 + 游戏内手工验证为主。

建议验证步骤：
1. `/reload`
2. `/qd`
3. 检查顶部按钮是否显示为 `分类(数量)`
4. 对照背包物品，确认数量口径是“该分类全部候选数”
5. 点击按钮，确认选中状态有明显按下效果
6. 打开候选窗口，确认按钮样式与数量显示保持一致
