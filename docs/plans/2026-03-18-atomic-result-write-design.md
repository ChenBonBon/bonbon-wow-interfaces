# 原子写入设计

## 背景

抓取过程中现在会实时刷新两个关键文件：

- `manifest.json`
- `items.by-task.json`

虽然这些写入发生在主协调线程中，不存在当前进程内多个 worker 同时写同一个文件的问题，但仍然存在两个风险：

1. 进程在写入过程中被中断，留下半截 JSON
2. 读者在写入中途恰好读取到不完整内容

## 目标

将上述两个文件的回写改成原子写入：

- 先在同目录生成临时文件
- 完整写入内容
- 再通过 `replace` 替换目标文件

这样读者要么看到旧版本，要么看到新版本，不会看到半截内容。

## 方案

新增共享 helper：

- `_atomic_write_text(file_path, content)`

行为：

1. 在目标文件同目录创建临时文件
2. 写入完整文本
3. 使用 `Path.replace()` 原子替换目标文件
4. 在 `finally` 中清理残留临时文件

应用范围：

- `_write_manifest()`
- `_write_items_by_task()`

## 为什么现在不加文件锁

当前写入是由抓取主线程串行触发的，而不是多个 worker 线程并发写同一文件，所以线程内竞争不是主要风险。相比之下，原子写入能更直接解决“半截文件”和“读到损坏 JSON”的问题，复杂度也更低。

## 验证

新增测试，确认：

- `_write_manifest()` 会通过 `replace` 完成写入
- `_write_items_by_task()` 会通过 `replace` 完成写入
